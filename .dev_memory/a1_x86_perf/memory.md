# A1 x86 perf Memory

## Status

A1 is implemented on `stage/a1-x86-perf`.

## Implemented

- `common/device_runner.py`
  - `DeviceRunner.shell/push/pull`.
  - `backend=local` implemented.
  - `backend=ssh|sdb` kept as explicit A3 stubs.
  - Device profiles load from `.perf-skill/devices/<name>.yaml`.
- `skills/perf-hotspot-analyzer/scripts/preflight.py`
  - Detects `perf --version`, `perf_event_paranoid`, CAP_PERFMON, and callgraph mode.
  - Chooses `fp -> dwarf -> none` for `callgraph: auto`.
  - Never invokes sudo or changes host state.
- `skills/perf-hotspot-analyzer/scripts/capture.py`
  - Uses `DeviceRunner` local backend.
  - Runs target-side `runner.sh` for live perf capture.
  - Produces directory Capture Bundle artifacts and validates `manifest.json`.
  - Keeps `perf-script.txt` as the primary analysis source and derives `out.folded` on host when needed.
- `skills/perf-hotspot-analyzer/scripts/postprocess.py`
  - Parses `perf-script.txt` callgraphs.
  - Classifies every frame via `.perf-skill/ownership.yaml`.
  - Performs caller-attribution according to `attribution_strategy`.
  - Resolves deterministic source anchors from unique C/C++ function definitions.
- `skills/perf-hotspot-analyzer/scripts/build_report.py`
  - Builds canonical `performance-findings.json`.
  - Derives `report_types` from finding kinds.
  - Writes `analysis-report.md` with diagnosis marked `pending`.
  - Writes `run-report.json` with per-finding actionability decisions.
- `cli/perf_hotspot_analyzer.py`
  - Adds `capture`, `analyze`, and `report` subcommands while retaining `validate`.
- `tests/fixtures/golden/live-perf/x86-hotspot/`
  - Loop-heavy C sample.
  - Local device profile and ownership profile.
  - Pre-captured bundle for CI.

## Handoff Notes

- CI should consume the pre-captured x86 bundle; live perf is skipped unless `PERF_SKILL_ENABLE_LIVE_PERF=1`.
- `ssh` and `sdb` are intentionally not implemented in A1.
- `diagnosis` and `candidate_optimizations` remain host Agent work and are not generated by Python scripts.
- A2 should start only after A1 review and must not assume Tizen transport is available.
