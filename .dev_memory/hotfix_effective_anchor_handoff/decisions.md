# Hotfix Effective Anchor Handoff Decisions

## A Report Must Persist The Derived Effective Anchor

- Symptom: a real Tizen armv7l ffmpeg run produced owned findings with
  `code_anchors`, but `performance-findings.json` left every `effective_anchor`
  empty. B therefore saw no target anchor and downgraded patch suggestions.
- Root cause: `build_report.py` emitted `code_anchors` and
  `attribution_anchor`, but never called
  `schema_validate.derive_effective_anchor()` before writing the canonical
  report.
- Fix: `_finding_from_hotspot()` now derives and writes
  `finding.effective_anchor` for every finding that has a deterministic
  anchor. Analysis markdown and run-report anchor summaries read the same
  effective-anchor view.
- Test: `test_build_report_populates_effective_anchor_for_realboard_ffmpeg_shape`
  asserts `ff_h264_filter_mb` resolves to
  `libavcodec/h264_loopfilter.c:716`.

## B Must Respect Serialized Effective Anchors

- Symptom: the B side could recompute or miss the handoff anchor instead of
  using the A side's canonical `effective_anchor`.
- Root cause: `ingest.anchor_findings()` and `make_patch._chosen_anchor()` only
  derived from attribution/code anchors and ignored a serialized
  `effective_anchor` field.
- Fix: B now prefers `finding.effective_anchor`, then falls back to
  `derive_effective_anchor()`, then to the first `code_anchors` entry. Advisory
  patches also keep `chosen_anchor` when an anchor exists.
- Test: `test_anchor_findings_prefers_serialized_effective_anchor` and
  `test_make_patch_handoff_uses_effective_anchor_and_stays_advisory_without_candidate`
  cover the handoff path.

## A-Originated Reports Without Candidates Stay Advisory

- Symptom: once A writes anchors correctly, B3 could create placeholder comment
  diffs for A findings even though A intentionally does not generate
  `candidate_optimizations`.
- Root cause: the patch generator treated any actionable finding with a
  high-confidence anchor as diff-capable, even when the source report came
  directly from `perf-hotspot-analyzer/build_report`.
- Fix: reports generated by `perf-hotspot-analyzer/build_report` require a
  candidate optimization before diff generation. Missing candidates produce an
  advisory-only patch with the chosen anchor retained.
- Test: the ffmpeg handoff regression asserts `status=advisory-only`,
  `chosen_anchor=libavcodec/h264_loopfilter.c:716`,
  `validation_status=not-run`, and `measured_impact=null`.

## Patch Ordering Prioritizes Owned Actionable Findings

- Symptom: system and not-actionable findings can dominate noisy realboard
  profiles.
- Fix: patch generation sorts owned/actionable findings first and places
  system/not-actionable findings last, preserving existing contracts that expect
  advisory entries for all findings.
- Test: `test_make_patch_orders_owned_actionable_before_system_noise`.
