# A3 Decisions

## D001: Shell Out To Existing Device Tools

`DeviceRunner` uses subprocess calls to `ssh`, `scp`, and `sdb` rather than
adding protocol libraries.  This matches the design, keeps device setup visible,
and lets tracing record exact backend commands.

## D002: No Silent Retry Or Privilege Escalation

Backend failures return stderr with remediation instead of retrying, running
sudo, or mutating target policy.  Tizen sshd/OpenSSH setup remains an explicit
operator prerequisite.

## D003: `perf-script.txt` Stays Primary

A3 postprocess consumes `perf-script.txt` first.  `out.folded` remains a
flamegraph/aggregation artifact and is host-generated by default when the target
does not have stackcollapse.

## D004: Path Mapping Is Best-Effort But Structured

Every DSO/build-id entry can produce a `tizen.path_mapping` row.  Rows may have
empty `debug_path` or `source_path` when debuginfo/source is unavailable, but the
mapping still records target path, host sysroot projection, and build-id.

## D005: Offline Fixture Uses Host-Built Debuginfo

The A3 fixture stores a tiny x86_64 shared object with the requested build-id.
This keeps CI deterministic while testing the same host-side build-id and
`addr2line` code path.  The live guide covers real Tizen/ARM debuginfo.
