# M0.5 Golden Fixtures Test Guide

## Scope

M0.5 establishes the DESIGN §10.4 golden fixture baseline:

- Positive fixtures ①-⑦ must pass `common/schema_validate.py`.
- Negative fixtures ⑧-⑫ must be rejected by `common/schema_validate.py`.

This milestone does not implement perf capture, ingestion adapters, anchor
scoring, patch generation, Tizen device logic, or automatic patch application.

## Prerequisites

- Python 3.11+.
- Dev dependencies from `requirements-dev.txt`.
- No Tizen, GBS, `sdb`, debuginfo, or real `perf` artifacts are required.

## Setup

```bash
uv venv .venv --python python3
uv pip install --python .venv/bin/python -r requirements-dev.txt
```

## Functional Fixture Validation

```bash
.venv/bin/python -m pytest tests/functional/test_golden_fixtures.py
```

Expected result:


## CLI Smoke

Positive:

```bash
.venv/bin/python -m perf_hotspot_analyzer validate \
  --input tests/fixtures/golden/positive/01-hotspot-binary-size-mixed/performance-findings.json \
  --output-dir /tmp/m05_cli_positive
```

Expected: exit code `0`, plus `/tmp/m05_cli_positive/run-report.json` and a
JSONL trace file.

Negative:

```bash
.venv/bin/python -m perf_hotspot_analyzer validate \
  --input tests/fixtures/golden/negative/12-binary-size-large-missing-threshold/performance-findings.json \
  --output-dir /tmp/m05_cli_negative
```

Expected: exit code `1`, with an error mentioning missing `threshold`.

## Fixture Layout

Each fixture directory contains:

- `README.md`: what DESIGN §10.4 case it covers
- `notes.md`: human context for future milestone users
- `expected.json`: document name, document type, and pass/fail expectation
- `performance-findings.json` or `patches.json`: contract document under test
- optional raw input data for later parser milestones

## Pass Criteria

- 7 positive fixtures pass.
- 5 negative fixtures are rejected.
- No schema files are changed in M0.5.
- No business logic beyond fixture validation tests is implemented.
